# 大乐透选号台 · GitHub Pages 独立版

这是从原 `dlt-picker` 复制并单独改造的静态版本。原代码、原私有站点与原数据均保留，没有被替换。

新版可以发布到 GitHub Pages，无需 ChatGPT 登录、付费服务器或自购域名。仅提供选号和方案记录，不进行购票交易。GitHub Pages 在不同地区和网络下的可达性仍需以实际网址测试为准。

## 本版功能

- 保留历史频次推荐、1—20组按需生成、自选投注、复式、前后区及双区胆拖、追加、1—99倍、注数与金额核算。
- 保留数据补录、修订、JSON/CSV导入、数据导出、方案保存、复制、导入导出、普通奖级核对。
- 默认评分仍为20%全历史频率＋50%近100期频率＋30%近30期频率，窗口及权重可以修改；遗漏只作描述。
- 新版内置数据已核对至第26122期（2026-10-26），共754期。旧752期样本保留为回归测试边界，原回测数据仍只代表初始策略，不能理解为新增数据的再次验证。
- 数据与记录保存在当前网站源的浏览器localStorage，不自动跨设备同步。公开仓库不包含浏览器中的个人方案记录。

## GitHub Pages 发布步骤

1. 登录你的 GitHub 账号，新建一个名为 `dlt-pages` 的 **Public（公开）** 仓库。免费 GitHub Pages 通常使用公开仓库。可以勾选初始化README。
2. 把本文件夹的源文件推送到该仓库的 `main` 分支。必须保留 `.github/workflows/pages.yml`，不上传 `node_modules`。文件夹里的 `.gitignore` 已排除依赖和构建缓存。
3. 打开仓库 `Settings → Pages → Build and deployment → Source`，选择 **GitHub Actions**。
4. 打开仓库 `Actions → 发布与更新大乐透选号台 → Run workflow`，选择 `main` 后运行。
5. 等待 `build` 和 `deploy` 两个任务成功，访问 `https://你的用户名.github.io/dlt-pages/`。如果仓库使用别的名字，地址中的项目名相应变化。资源已使用相对路径，无需为项目目录修改源码。

只有仓库和网页公开；本地方案不会自动上传。发布前请确认没有把原站点配置、凭据、个人导出备份混入仓库。本包没有包含原站点的 `.openai` 配置、Git历史或登录配置。

如果让我继续上传，提供新建仓库的链接即可；GitHub连接还需能访问该新仓库。当前原站点不必关闭。

## 开奖更新方式

GitHub Pages 无服务端，所以“更新开奖数据”按钮现在读取本站 `data/draws.json`，而不是调用原站点的 `/api/draws`。

仓库中的 GitHub Actions 工作流会在以下情况核对官方接口并构建发布：

- 推送 `main` 分支；
- 手动 `Run workflow`；
- 每天北京时间09:37和22:37调度。

调度时间可能延迟，不能当作实时开奖接口。公开仓库长期无活动时，GitHub可能暂停定时工作流，可在Actions页重新启用。网页会显示当前数据截止期号及最近一次后台检查状态。

### 动态接口返回567时

程序优先读取官方动态接口；遇到567、网络失败或无有效响应时，自动切换 `pdf.sporttery.cn` 上的官方开奖公告PDF。无需付费接口、代理或个人Token。PDF解析库仅供后台使用，不进入网页资源。

- 先用已有最新一期公告核对期号、日期、前后区号码，再按期号连续读取新公告并补齐已知年内缺口；支持跨年。
- 仅提取“本期开奖号码”一行，不把出球顺序、奖级表或未经核对的第三方数据当作开奖。
- 下一期待公布公告的404表示本次未读到新公告；567、超时、伪PDF、数据冲突会明确报错。两个来源都失败时保留现有号码，发布失败状态，下次调度重试。
- 页面“更新开奖数据”仍读取本站已发布文件，同时读取后台状态；显示最近检查时间、当前通道及失败原因。该按钮不会从浏览器直接触发GitHub任务。

公告发布可能晚于开奖，两个官方通道也可能同时不可达，因此无法保证实时更新；必要时可在Actions页手动运行任务，手动补录和导入功能仍保留。

新增官方数据和每次检查状态会提交回仓库，重新构建后供网页读取。推送所用的是仓库内置的 `GITHUB_TOKEN`，无需个人Token。整个部署只使用GitHub标准免费运行器，发布文件保留1天，不使用付费运行器、外部数据库或付费API。

## 从旧版迁移个人记录

1. 旧站“开奖数据”中导出JSON备份；“方案记录”中导出全部。
2. 在新版“开奖数据”导入开奖备份；在“方案记录”导入方案备份。
3. 如有自定义频次参数，在新版“规则与方法”中重新填写。新旧网址的浏览器存储互不相通。

旧数据与新版中已有相同期号会去重，冲突整批拒绝。可在界面核对官方公告后手动修订。

## 本地运行与构建

需要 Node.js 22.13以上及pnpm 11.25.0。构建与页面访问不需要ChatGPT账号。

```text
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm typecheck
pnpm build
pnpm verify-build
pnpm preview
```

默认开发预览是 `http://127.0.0.1:5174/`，生产构建预览是 `http://127.0.0.1:4174/`。`dist/` 是最终静态文件，亦可放到任何普通静态网站服务器；不要用双击HTML的file://方式代替HTTP服务器。

仅更新数据可以运行 `pnpm update-data`。读取官方数据需要网络，但已有数据下的选号和计算在浏览器本地完成。

## 目录

- `src/`：网页界面与样式；
- `lib/engine.mjs`：选号、投注计算、奖级核对及校验；
- `data/`：编译时内置数据；
- `public/data/`：发布后给更新按钮读取的数据和来源状态；
- `scripts/update-data.mjs`：官方数据核对及安全合并；
- `.github/workflows/pages.yml`：免费构建、数据更新及Pages发布；
- `tests/`：计算、迁移及更新逻辑测试；
- `dist/`：构建产生的静态网站，不作为源代码提交。

## 方法边界

历史频次不代表下一期概率；初始150期策略回测中奖51注，随机对照均值约50.2注，尚未显示稳定优势。普通奖级核对不等于奖金核算，追加、特别派奖及实际兑付以当期官方公告为准。

- https://www.lottery.gov.cn/kj/kjlb.html?dlt
